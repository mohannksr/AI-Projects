1. The big picture

A coding agent is a loop around a model that can ask for tools:

you> "The tests are failing. Find the bug and fix it."
  │
  ▼
agent.ask()
  │  responses.create(input=your message, tools=[...], previous_response_id=last turn)
  ▼
model returns function_call: run_command("pytest -q")
  │
  ▼
Toolbox.run()  ── guards ──► approval? ──► subprocess (shell=False) ──► "exit code 1 ... 1 failed"
  │
  │  responses.create(input=[function_call_output], previous_response_id=this response)
  ▼
model returns function_call: read_file → write_file (you approve a diff) → run_command(pytest)
  │
  ▼
model returns plain text ──► loop stops ──► "agent> Fixed: tip = total * tip_percent / 100. 4 passed."

Three ideas carry the whole project:

  1. The model only asks; your code decides. Tools are functions in tools.py. The model sends a name and arguments, and nothing happens until your guards say yes.
  2. Results go back as text. Errors, rejections and test failures become tool results. The model reads them and adapts. That's how it "debugs".
  3. A human approves changes. Writes and test runs pause for Allow? [y/N]. That rule lives in code, so no prompt can talk its way past it.

4. Why the naive version is dangerous

Most first agents write their tools like this. It looks safe because there's an allow-list and a resolve():

ALLOWED = ["ls", "cat", "echo"]

def naive_run_command(cmd):
    if cmd.split()[0] not in ALLOWED:          # only checks the FIRST word
        return "not allowed"
    return subprocess.run(cmd, shell=True, capture_output=True, text=True).stdout

def naive_read_file(path):
    return (Path.cwd() / path).resolve().read_text()   # resolve() but no containment check

Run it in a folder next to a secret file, and all three attacks work:

>>> naive_run_command('ls && echo PWNED > pwned.txt')
'app.py\n'
>>> files now: ['app.py', 'pwned.txt']

>>> naive_run_command('echo oops > app.py')
>>> app.py now contains: 'oops\n'

>>> naive_read_file('../outside_secret.txt')
'TOP SECRET: db password = hunter2\n'
  • ls && …: the first word is ls, so the check passes. shell=True then runs the whole string, including the second command.
  • echo … > app.py: echo is allowed, and the shell's redirect overwrites your code.
  • ../outside_secret.txt: resolve() turns the path into a clean absolute path, but nobody checks that it is still inside the project.

The model doesn't have to be malicious for this to bite. It can be confused, or steered by text hidden in a file it reads (see test 5).

5. tools.py: tools and guards

Telling the model what tools exist

Each tool is described with a JSON schema in the Responses API format. strict: True forces the model to send exactly these arguments: every property listed in required, with additionalProperties: false.

_function("run_command",
          "Run one command in the workspace. Allowed: ls, cat, head, tail, wc, grep, find, pwd, "
          "and pytest (the user must approve). No pipes, redirects or chaining.",
          {"command": {"type": "string", "description": "A single command, e.g. 'pytest -q' ..."}}),
{"type": "web_search"},   # hosted tool: OpenAI runs the search, our code does nothing

The description is also a guard. It tells the model the rules up front, so it rarely tries a blocked command. The code still enforces every rule regardless.

Errors are answers, not crashes

Toolbox.run() catches ToolError, timeouts and OS errors, and returns them as text: "error: '.env' looks like a secret ...". The model reads that result like any other and changes course. If the tool raised instead, the whole turn would crash, and the model would never learn why.

Full source: tools.py
"""
tools.py - the agent's hands: what it may do on your machine, and the guards.

Author: Shivank Agrawal
Project: Mini Cursor (coding agent in your terminal) - Future with Shivank

The model never touches your computer directly. It can only ASK for one of
these tools by name. Our code checks the request and then runs it:

    list_files(path)          list a folder
    read_file(path)           read a text file
    find_files(pattern)       glob search, e.g. "**/*.py"
    write_file(path, content) create/overwrite a file  -> you approve a diff first
    run_command(command)      read-only commands run freely; pytest needs approval
    web_search                hosted by OpenAI (no code here, see TOOL_SCHEMAS)

Guards, because the model's requests are untrusted input:
    1. Workspace jail : every path must resolve INSIDE the workspace folder.
    2. Secret files   : .env, keys, .ssh, .aws, .git are never read or listed.
    3. No shell       : commands run as an argv list (shell=False); characters
                        like | ; & > < ` $ are rejected, so no chaining/redirects.
    4. Allow-list     : only a few read-only programs, plus pytest with approval.
    5. Human approval : every file write and every test run is shown to you first.
    6. Limits         : timeouts and output size caps.
"""

import difflib
import shlex
import subprocess
from pathlib import Path
from typing import Callable

MAX_OUTPUT_CHARS = 10_000  # long outputs are cut so they don't flood the model's context
COMMAND_TIMEOUT = 30  # seconds

READ_ONLY_COMMANDS = {"ls", "cat", "head", "tail", "wc", "grep", "find", "pwd"}
APPROVAL_COMMANDS = {"pytest"}  # runs project code, so you approve each run
FORBIDDEN_CHARS = set("|;&<>`$\n")
BLOCKED_FIND_OPTIONS = {"-exec", "-execdir", "-delete", "-ok", "-okdir", "-fprint", "-fprintf", "-fls"}
SECRET_NAMES = {".env", ".ssh", ".aws", ".git", "id_rsa", "id_ed25519"}
SECRET_SUFFIXES = (".pem", ".key")


class ToolError(Exception):
    """A request the guards refused. The message is sent back to the model."""


# ---------------------------------------------------------------------------
# Tool descriptions for the model (Responses API format).
# strict=True: the model must send exactly these arguments, all of them.
# ---------------------------------------------------------------------------
def _function(name: str, description: str, properties: dict) -> dict:
    return {
        "type": "function",
        "name": name,
        "description": description,
        "strict": True,
        "parameters": {
            "type": "object",
            "properties": properties,
            "required": list(properties),
            "additionalProperties": False,
        },
    }


PATH = {"type": "string", "description": "Path relative to the workspace root, e.g. 'src/app.py' or '.'"}

TOOL_SCHEMAS = [
    _function("list_files", "List the files and folders inside a folder of the workspace.", {"path": PATH}),
    _function("read_file", "Read a text file from the workspace.", {"path": PATH}),
    _function("find_files", "Find files by glob pattern, e.g. '**/*.py' or 'tests/test_*.py'.",
              {"pattern": {"type": "string", "description": "Glob pattern relative to the workspace root"}}),
    _function("write_file", "Create or overwrite a file with the FULL new content. The user must approve the change.",
              {"path": PATH, "content": {"type": "string", "description": "The complete new file content"}}),
    _function("run_command",
              "Run one command in the workspace. Allowed: ls, cat, head, tail, wc, grep, find, pwd, "
              "and pytest (the user must approve). No pipes, redirects or chaining.",
              {"command": {"type": "string", "description": "A single command, e.g. 'pytest -q' or 'grep -n def app.py'"}}),
    {"type": "web_search"},  # hosted tool: OpenAI runs the search, our code does nothing
]


class Toolbox:
    def __init__(self, workspace: Path, approve: Callable[[str], bool]):
        self.root = workspace.resolve()
        self.approve = approve  # asks the human; returns True/False

    # -- guards --------------------------------------------------------------
    def safe_path(self, path: str) -> Path:
        """Resolve a path and make sure it stays inside the workspace and isn't a secret."""
        resolved = (self.root / path).resolve()
        if not resolved.is_relative_to(self.root):
            raise ToolError(f"'{path}' is outside the workspace. Use paths inside {self.root.name}/.")
        relative_parts = resolved.relative_to(self.root).parts
        if any(part in SECRET_NAMES or part.endswith(SECRET_SUFFIXES) for part in relative_parts):
            raise ToolError(f"'{path}' looks like a secret (keys, .env, .git). Access denied.")
        return resolved

    def is_secret(self, path: Path) -> bool:
        return any(part in SECRET_NAMES or part.endswith(SECRET_SUFFIXES)
                   for part in path.relative_to(self.root).parts)

    # -- tools ---------------------------------------------------------------
    def list_files(self, path: str) -> str:
        folder = self.safe_path(path)
        if not folder.is_dir():
            raise ToolError(f"'{path}' is not a folder.")
        entries = []
        for item in sorted(folder.iterdir(), key=lambda p: (p.is_file(), p.name)):
            if self.is_secret(item) or item.name in ("__pycache__", ".pytest_cache"):
                continue
            entries.append(f"{item.name}/" if item.is_dir() else f"{item.name}  ({item.stat().st_size} bytes)")
        return "\n".join(entries) or "(empty folder)"

    def read_file(self, path: str) -> str:
        file = self.safe_path(path)
        if not file.is_file():
            raise ToolError(f"'{path}' does not exist or is not a file.")
        return file.read_text(encoding="utf-8", errors="replace")

    def find_files(self, pattern: str) -> str:
        if pattern.startswith("/") or ".." in pattern:
            raise ToolError("Patterns must be relative to the workspace (no '/' at the start, no '..').")
        matches = [p for p in sorted(self.root.glob(pattern))
                   if p.is_file() and not self.is_secret(p) and "__pycache__" not in p.parts]
        return "\n".join(str(p.relative_to(self.root)) for p in matches[:200]) or "(no matches)"

    def write_file(self, path: str, content: str) -> str:
        file = self.safe_path(path)
        old = file.read_text(encoding="utf-8") if file.exists() else ""
        if old == content:
            return f"No change: {path} already has this content."
        # Show the human exactly what will change, as a unified diff.
        diff = "".join(difflib.unified_diff(
            old.splitlines(keepends=True), content.splitlines(keepends=True),
            fromfile=f"a/{path}" if old else "/dev/null", tofile=f"b/{path}"))
        if not self.approve(f"write {path}\n{diff}"):
            return f"The user REJECTED the change to {path}. Ask what they want instead."
        file.parent.mkdir(parents=True, exist_ok=True)
        file.write_text(content, encoding="utf-8")
        return f"Wrote {path} ({len(content.splitlines())} lines)."

    def run_command(self, command: str) -> str:
        if any(ch in FORBIDDEN_CHARS for ch in command):
            raise ToolError("Pipes, redirects, chaining (; && |) and $ are not allowed. Send one simple command.")
        argv = shlex.split(command)
        if not argv:
            raise ToolError("Empty command.")
        program = argv[0]
        if program not in READ_ONLY_COMMANDS | APPROVAL_COMMANDS:
            allowed = ", ".join(sorted(READ_ONLY_COMMANDS | APPROVAL_COMMANDS))
            raise ToolError(f"'{program}' is not allowed. Allowed commands: {allowed}.")
        if program == "find" and BLOCKED_FIND_OPTIONS & set(argv):
            raise ToolError("find may only search (no -exec, -delete or -fprint).")
        if program == "grep":  # a recursive grep must not read secret files
            argv[1:1] = ["--exclude=.env*", "--exclude=*.pem", "--exclude=*.key", "--exclude=id_*",
                         "--exclude-dir=.git", "--exclude-dir=.ssh", "--exclude-dir=.aws"]
        for arg in argv[1:]:  # any argument that looks like a path must stay inside the workspace
            if not arg.startswith("-") and ("/" in arg or arg.startswith(".") or (self.root / arg).exists()):
                self.safe_path(arg)
        if program in APPROVAL_COMMANDS and not self.approve(f"run `{command}`"):
            return f"The user REJECTED running `{command}`."
        completed = subprocess.run(argv, cwd=self.root, capture_output=True, text=True,
                                   timeout=COMMAND_TIMEOUT, shell=False)
        output = (completed.stdout + completed.stderr).strip() or "(no output)"
        if len(output) > MAX_OUTPUT_CHARS:
            output = output[:MAX_OUTPUT_CHARS] + "\n[output truncated]"
        return f"exit code {completed.returncode}\n{output}"

    # -- dispatcher ----------------------------------------------------------
    def run(self, name: str, args: dict) -> str:
        """Run a tool by name. Errors become text the model can read and react to."""
        tool = {"list_files": self.list_files, "read_file": self.read_file, "find_files": self.find_files,
                "write_file": self.write_file, "run_command": self.run_command}.get(name)
        if tool is None:
            return f"error: unknown tool '{name}'"
        try:
            result = tool(**args)
        except ToolError as error:
            return f"error: {error}"
        except subprocess.TimeoutExpired:
            return f"error: command timed out after {COMMAND_TIMEOUT}s"
        except (OSError, ValueError) as error:  # ValueError: bad quotes in shlex
            return f"error: {error}"
        if len(result) > MAX_OUTPUT_CHARS:
            result = result[:MAX_OUTPUT_CHARS] + "\n[output truncated]"
        return result

6. agent.py: the loop

One question, many rounds

response = self._call_model(user_message, self.last_response_id)
for _ in range(MAX_STEPS):
    calls = [item for item in response.output if item.type == "function_call"]
    if not calls:
        break                                   # plain text answer: done
    outputs = []
    for call in calls:                          # the model may ask for several tools at once
        result = self.tools.run(call.name, json.loads(call.arguments))
        outputs.append({"type": "function_call_output", "call_id": call.call_id, "output": result})
    response = self._call_model(outputs, response.id)
self.last_response_id = response.id
return response.output_text
  • call_id pairs the result with the request. If the model asks for two files in one round, both results go back together, each with its own call_id.
  • previous_response_id is the memory. OpenAI keeps the conversation, including the model's reasoning items, on its side. We only send what is new: the user's message or the tool outputs. A follow-up question passes the last turn's id, so "now add a test for it" just works. new in the chat resets it to None.
  • instructions go with every call, because previous_response_id doesn't carry the system prompt over.
  • Hosted web_search runs inside the API call. It shows up as a web_search_call item next to the answer, so our loop only prints it.
  • Step limit. After MAX_STEPS rounds, any pending calls get a "step limit reached" output, and one last call with tool_choice="none" forces a text summary. If you didn't do this, the next question would fail with "No tool output found for function call".

Full source: agent.py
"""
agent.py - the agent loop: ask the model, run the tools it asks for, repeat.

Author: Shivank Agrawal
Project: Mini Cursor (coding agent in your terminal) - Future with Shivank

    you: "the tests fail, fix it"
        |
        v
    model (gpt-5.4-mini) --function_call--> our code runs the tool (with guards)
        ^                                         |
        +----------- function_call_output --------+
        |
        (repeat until the model answers with text, max MAX_STEPS rounds)
        v
    final answer

We use OpenAI's Responses API. Each request passes `previous_response_id`, so
OpenAI keeps the conversation (and the model's reasoning) on its side; we only
send what is NEW: the user's message, or the results of the tools it asked for.
"""

import json
from pathlib import Path
from typing import Callable

from openai import OpenAI

from tools import TOOL_SCHEMAS, Toolbox

MAX_STEPS = 12  # tool rounds per question; stops a confused model from looping forever

SYSTEM_PROMPT = """You are Mini Cursor, a careful coding agent working inside the
folder {workspace}. All paths are relative to that folder.

How to work:
1. Explore before you change anything: list_files, find_files, read_file.
2. To change code, call write_file with the COMPLETE new file content.
   The user reviews a diff and may reject it.
3. Verify: after a change, run the tests with `pytest -q` when tests exist.
4. Use web_search only for facts that may be newer than your training data
   (latest versions, recent API changes).
5. Never try to read secrets (.env, keys) or work outside the workspace. If a
   tool returns an error, read it, adjust, and try a different approach.

Answer briefly: what you found, what you changed, and the result."""


class CodingAgent:
    def __init__(self, workspace: Path, model: str, approve: Callable[[str], bool],
                 on_step: Callable[[str, dict], None]):
        self.client = OpenAI()  # reads OPENAI_API_KEY from the environment
        self.model = model
        self.tools = Toolbox(workspace, approve)
        self.instructions = SYSTEM_PROMPT.format(workspace=self.tools.root.name)
        self.on_step = on_step  # callback so the CLI can show each step live
        self.last_response_id = None  # conversation memory lives on OpenAI's side

    def new_conversation(self) -> None:
        self.last_response_id = None

    def _call_model(self, input_items, previous_id, allow_tools: bool = True):
        # instructions are NOT carried over by previous_response_id, so send them every time
        return self.client.responses.create(
            model=self.model,
            instructions=self.instructions,
            input=input_items,
            tools=TOOL_SCHEMAS,
            tool_choice="auto" if allow_tools else "none",
            previous_response_id=previous_id,
        )

    def ask(self, user_message: str) -> str:
        """Handle one user message: loop until the model gives a final answer."""
        response = self._call_model(user_message, self.last_response_id)

        for _ in range(MAX_STEPS):
            # Hosted web searches already happened on OpenAI's side; just show them.
            for item in response.output:
                if item.type == "web_search_call":
                    query = getattr(getattr(item, "action", None), "query", "") or ""
                    self.on_step("web_search", {"query": query})

            calls = [item for item in response.output if item.type == "function_call"]
            if not calls:
                break  # no more tool requests: the model has answered

            outputs = []
            for call in calls:  # the model may ask for several tools at once
                args = json.loads(call.arguments)
                self.on_step("tool_call", {"name": call.name, "args": args})
                result = self.tools.run(call.name, args)
                self.on_step("tool_result", {"name": call.name, "result": result})
                outputs.append({"type": "function_call_output", "call_id": call.call_id, "output": result})

            response = self._call_model(outputs, response.id)
        else:
            # Step limit hit: answer the pending calls and force a text-only reply,
            # so the conversation is never left with unanswered tool calls.
            calls = [item for item in response.output if item.type == "function_call"]
            outputs = [{"type": "function_call_output", "call_id": c.call_id,
                        "output": "Step limit reached. Do not call tools; summarise progress for the user."}
                       for c in calls]
            if outputs:
                response = self._call_model(outputs, response.id, allow_tools=False)

        self.last_response_id = response.id
        return response.output_text

7. main.py: the terminal app

  • show_step() prints each tool call (-> read_file(path="bill_splitter.py")) and a one-line result:
    • a line count for reads
    • exit code · last line for commands, e.g. exit code 1 · 1 failed, 3 passed
    • errors in red
  • approve() prints the request, colours the diff (green +, red -) and waits for y. Anything else counts as "no".
  • Colours exist only in the terminal. The model receives plain text, because ANSI codes would waste tokens and confuse it.
  • There are two modes:
    • Interactive chat: new starts a fresh conversation and exit quits.
    • One-off: questions passed as arguments share one conversation.
Full source: main.py
"""
main.py - the terminal app: chat with the coding agent, see every step,
approve every change.

Author: Shivank Agrawal
Project: Mini Cursor (coding agent in your terminal) - Future with Shivank

Usage (from this folder):
    python main.py --workspace sample_project                 # interactive chat
    python main.py --workspace sample_project "What does this project do?"
                                                               # ask, then exit
Inside the chat: type `new` for a fresh conversation, `exit` to quit.
"""

import argparse
import json
import os
from pathlib import Path

from dotenv import load_dotenv

from agent import CodingAgent

# ANSI colours for the terminal (only for display; the model never sees them)
GREEN, CYAN, YELLOW, RED, DIM, BOLD, RESET = (
    "\033[32m", "\033[36m", "\033[33m", "\033[31m", "\033[2m", "\033[1m", "\033[0m")


def show_step(kind: str, data: dict) -> None:
    """Print each agent step as it happens."""
    if kind == "tool_call":
        args = ", ".join(f"{k}={json.dumps(v)[:60]}" for k, v in data["args"].items() if k != "content")
        print(f"{CYAN}  -> {data['name']}({args}){RESET}")
    elif kind == "tool_result":
        lines = data["result"].splitlines() or [""]
        failed = lines[0].startswith("error") or "REJECTED" in lines[0]
        if failed:
            summary = lines[0]
        elif data["name"] == "read_file":
            summary = f"read {len(lines)} lines"
        elif data["name"] == "run_command":
            summary = f"{lines[0]} · {lines[-1]}"  # e.g. "exit code 1 · 1 failed, 3 passed in 0.02s"
        else:
            summary = lines[0] + (f"  (+{len(lines) - 1} more lines)" if len(lines) > 1 else "")
        print(f"{RED if failed else DIM}  <- {summary[:110]}{RESET}")
    elif kind == "web_search":
        print(f"{CYAN}  -> web_search({json.dumps(data['query'])}){RESET}")


def approve(request: str) -> bool:
    """Ask the human before a file write or a test run. Shows the diff in colour."""
    title, _, diff = request.partition("\n")
    print(f"\n{YELLOW}{BOLD}  Approval needed: {title}{RESET}")
    for line in diff.splitlines():
        colour = GREEN if line.startswith("+") else RED if line.startswith("-") else DIM
        print(f"  {colour}{line}{RESET}")
    return input(f"{YELLOW}  Allow? [y/N] {RESET}").strip().lower() in ("y", "yes")


def main() -> None:
    load_dotenv(Path(__file__).parent / ".env")  # OPENAI_API_KEY
    parser = argparse.ArgumentParser(description="Mini Cursor: a coding agent in your terminal")
    parser.add_argument("questions", nargs="*", help="optional questions to ask, then exit")
    parser.add_argument("--workspace", default=".", help="folder the agent may work in")
    parser.add_argument("--model", default=os.getenv("CHAT_MODEL", "gpt-5.4-mini"))
    args = parser.parse_args()

    workspace = Path(args.workspace)
    agent = CodingAgent(workspace, args.model, approve=approve, on_step=show_step)
    print(f"{BOLD}Mini Cursor{RESET} · model {args.model} · workspace {workspace.resolve()}")

    def handle(question: str) -> None:
        print(f"\n{GREEN}{BOLD}you>{RESET} {question}")
        answer = agent.ask(question)
        print(f"\n{BOLD}agent>{RESET} {answer}")

    if args.questions:  # one-shot mode: same conversation for all questions
        for question in args.questions:
            handle(question)
        return

    print(f"{DIM}Type 'new' for a fresh conversation, 'exit' to quit.{RESET}")
    while True:
        try:
            question = input(f"\n{GREEN}{BOLD}you>{RESET} ").strip()
        except (EOFError, KeyboardInterrupt):
            break
        if question.lower() in ("exit", "quit"):
            break
        if question.lower() == "new":
            agent.new_conversation()
            print(f"{DIM}(new conversation){RESET}")
            continue
        if question:
            answer = agent.ask(question)
            print(f"\n{BOLD}agent>{RESET} {answer}")


if __name__ == "__main__":
    main()

def split_bill(total: float, people: int, tip_percent: float = 10) -> float:
    """Return how much each person pays, tip included, rounded to 2 decimals.

    Example: a Rs 1,000 dinner for 4 friends with a 10% tip -> 275.0 each.

10. Design choices vs alternatives

ChoiceAlternativeWhy we chose it
Responses API + previous_response_idChat Completions with a growing messages listLess code: we send only new items. Reasoning items are carried over automatically, and hosted tools like web_search are built in. Trade-off: the state lives on OpenAI's servers (store=true).
Hosted web_searchA search API like Exa or Tavily as a function toolOne key, no extra code, and results come with sources. Trade-off: less control over which sites are searched.
write_file with the full contentedit_file(old, new) exact-match replaceSimplest to build and always produces a complete file. Trade-off: it costs more tokens on big files, and the model can drop unrelated lines. The diff approval catches that.
Allow-list + shell=FalseDeny-list on top of a shellA deny-list always misses something (; && $() backticks, newlines…). Allow-listing programs and never invoking a shell removes the whole class of bugs.
Approval in code"Always ask before writing" in the promptA prompt is a request; code is a rule. Test 5 shows a fooled model trying anyway.
Errors returned as tool outputRaising exceptionsThe model can read an error and recover. An exception just ends the turn.
gpt-5.4-miniA larger frontier modelIt is fast and cheap, and good at tool calling for small repos. Switch to a bigger model for large refactors.
Plain terminal with ANSI coloursA web UI or the rich/textual librariesNo extra dependencies, and the learner can read all of it. A TUI library pays off once you add streaming, panels and history.

11. What a production version adds

  • A real sandbox. Run tools in a container with a read-only root filesystem and no network. Guards in code reduce risk, and a container contains it.
  • Targeted edits. An edit_file(path, old, new) tool that replaces exact snippets, plus git checkpoints and an undo.
  • Code search that understands code. Find functions and classes by name (tree-sitter/AST), and use RAG over the repo once it outgrows grep.
  • Model routing. A small fast model for questions and a stronger one for multi-file edits.
  • Streaming answers token by token, and a context budget that trims old tool outputs in long sessions.
  • Evals. A set of bug-fix tasks with tests, measuring pass rate, number of steps and cost per task.

These are exactly the upgrades in the next project, ai-code-assistant.

12. Interview follow-up questions

Q1. What makes this an agent rather than a chatbot?
The loop. The model chooses an action, our code executes it, and the result changes the model's next decision, until it judges the task done. In test 2 the failing assertion 2750.0 == 275.0 is what pointed it at the tip line.
Q2. Your allow-list includes ls. Why can't ls && rm -rf . get through?
Two independent reasons. The characters & | ; > < ` $ are rejected before parsing. And even if they weren't, we never start a shell: shlex.split + subprocess.run(argv, shell=False) would pass && to ls as a file name, not run it as an operator. The naive version fails because it checks one word and then hands the whole string to a shell.
Q3. Why isn't resolve() enough to stop path escapes?
resolve() normalises ../ and symlinks into an absolute path, but it doesn't say whether that path is allowed. You must check containment afterwards with resolved.is_relative_to(root). The naive demo reads ../outside_secret.txt for exactly this reason.
Q4. What is indirect prompt injection, and how does this project defend against it?
Instructions hidden in data the agent reads, such as a file, web page or issue comment, rather than in the user's message. The defence is layered:
  • Guards in code that hold even if the model is fooled
  • Human approval for anything that changes state
  • Secrets that are never readable
  • In production, a sandbox and no outbound network
Q5. Why must pytest need approval when cat doesn't?
pytest imports and runs project code, and the agent may have just written that code. Approving the run is approving code execution. Read-only commands can't change anything.
Q6. How does conversation memory work, and what are the trade-offs?
previous_response_id links each call to the last response, and OpenAI stores the chain, including reasoning items. The client stays tiny and the reasoning is preserved across tool calls. The costs:
  • The data is stored server-side, so check your data-retention needs.
  • You can't easily edit or trim history yourself.
The alternative is managing the full input list client-side.
Q7. What happens if the model keeps calling tools forever?
MAX_STEPS caps the rounds. On the limit we answer every pending call with "Step limit reached…" and make one final call with tool_choice="none", so the turn ends with a summary and no dangling calls that would break the next question.
Q8. The model wrote a fix that deletes an unrelated function. How would you catch that?
There are four layers:
  • The diff approval shows deleted lines in red before anything is written.
  • The tests run after the change.
  • An edit_file tool limits the blast radius to the snippet.
  • Git checkpoints make any change a one-command undo.
Q9. Why return tool errors as strings instead of raising?
Because the model is the one that has to fix the problem. "error: 'python' is not allowed. Allowed commands: …" tells it the rule and the alternatives, and the model retries correctly. An exception would end the turn and teach nothing.
Q10. How would you make this run fully offline, like the original "local" idea?
Point the OpenAI client at a local OpenAI-compatible server such as Ollama or vLLM (base_url), and use Chat Completions, which local servers support more widely than the Responses API. Drop the hosted web_search. The tools and guards don't change at all, which is a good sign the design is clean.
Q11. How would you evaluate a coding agent?
Build a set of small repos with a failing test each, in the style of SWE-bench. Measure:
  • resolve rate (tests pass afterwards)
  • steps and tokens per task
  • the rate of rejected or unsafe tool requests
Track these across prompt and model changes.
