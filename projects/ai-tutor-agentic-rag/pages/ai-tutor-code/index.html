1. The big picture

The system has two halves. An offline pipeline turns three documentation sites into searchable data. An online app lets an agent use that data to answer questions.

OFFLINE (run once, ~2-3 min)                                ONLINE (every question)
────────────────────────────                                ───────────────────────
GitHub docs (PEFT, TRL, OpenAI Agents SDK)                  Browser ──POST /api/chat──► FastAPI
   │ 1. download_docs.py  (sparse git clone)                   ▲            │
   ▼                                                           │ SSE events  ▼
data/docs/*.md                                                 │      Agent (LangGraph loop)
   │ 2. build_corpus.py   (clean + heading-aware chunks)       │      model: gpt-5.4-mini
   ▼                                                           │        │            │
documents.jsonl + chunks.jsonl                                 │        ▼            ▼
   │ 3. build_kb.py       ──► data/kb/ raw/ generated/ wiki/ ◄──── run_kb_command   │
   │ 4. build_vector_store.py ──► data/chroma (embeddings) ◄──────── retrieve_tutor_context
   ▼                                                                (vector + BM25 → RRF)

What happens when a learner asks a question

  1. The browser sends {message, threadId, sources} to POST /api/chat.
  2. FastAPI calls stream_chat(), which runs the agent with thread_id (for memory) and the selected sources (for filtering).
  3. The @dynamic_prompt middleware builds the system prompt, including the selected sources.
  4. The model reads the question and decides what to do. Usually it calls retrieve_tutor_context, sometimes 2–3 times in parallel, and sometimes it opens a page with run_kb_command.
  5. Each tool call and tool result is streamed to the browser as an event, so the learner watches the agent work.
  6. When the model has enough, it writes the answer. The tokens stream out as text-delta events, then a sources event carries the citations.

4. config.py: one source of truth

Every other file imports its settings from here. Three groups matter:

  • Models. CHAT_MODEL = "gpt-5.4-mini" runs the agent. EMBED_MODEL = "text-embedding-3-small" embeds both chunks and questions. They must be the same embedding model, or the question vector and the chunk vectors live in different spaces and search returns noise.
  • SOURCES. One dict entry per documentation site: the repo, docs folder, public URL base, and folders to skip. The pipeline, the UI's source picker, the retrieval filter and the prompt all read this dict, so adding a fourth library means one entry plus re-running the pipeline.
  • Knobs.
    • Chunk size: 600 tokens.
    • Retrieval: 15 + 15 candidates, RRF constant 60, top 6 passages, 4,000-token budget.
    • KB shell: 8 commands per question, 8 s timeout, 12,000-char output cap.

5. Step 1: download the docs (pipeline/download_docs.py)

A normal git clone of huggingface/trl pulls the whole repo with its history. We only need docs/source, so we use a sparse, shallow, blob-less clone:

git clone --depth 1 --filter=blob:none --sparse <repo> /tmp/trl   # latest commit, no file contents yet
git -C /tmp/trl sparse-checkout set docs/source                    # download only this folder

The clone goes into a tempfile.TemporaryDirectory(), so it cleans itself up. We copy only .md/.mdx files into data/docs/<source>/, keeping the folder structure because the folder path becomes part of the page URL later. If a source is already downloaded, it is skipped, so the step is safe to re-run.

[peft] copied 82 markdown files -> data/docs/peft
[trl] copied 57 markdown files -> data/docs/trl
[openai_agents] copied 38 markdown files -> data/docs/openai_agents
Done. 177 markdown files across 3 sources.
Full source: pipeline/download_docs.py
"""
Step 1 of the data pipeline: download the documentation markdown from GitHub.

Author: Shivank Agrawal
Project: AI Tutor (Agentic RAG) - Future with Shivank

For every source in config.SOURCES we do a "sparse" git clone, which pulls
only the docs folder instead of the whole repository, then copy the .md/.mdx
files into data/docs/<source>/ keeping their folder structure.

Run from the project root:
    python -m pipeline.download_docs
"""

import shutil
import subprocess
import tempfile
from pathlib import Path

from app.config import DOCS_DIR, ROOT, SOURCES


def is_excluded(relative_path: str, exclude_prefixes: list[str]) -> bool:
    """True if the file sits under a folder we decided to skip (e.g. translations)."""
    return any(relative_path.startswith(prefix) for prefix in exclude_prefixes)


def download_source(key: str, cfg: dict) -> int:
    """Sparse-clone one repo into a temp folder and copy its markdown docs."""
    target = DOCS_DIR / key
    if target.exists() and any(target.rglob("*.md*")):
        print(f"[{key}] already downloaded -> skipping")
        return len(list(target.rglob("*.md*")))

    # The clone lives in a temp folder that is deleted automatically afterwards.
    with tempfile.TemporaryDirectory() as tmp:
        clone_dir = Path(tmp) / key
        # --depth 1          : only the latest commit
        # --filter=blob:none : don't download file contents until needed
        # --sparse           : start with an empty working tree
        subprocess.run(
            ["git", "clone", "--quiet", "--depth", "1", "--filter=blob:none",
             "--sparse", cfg["repo"], str(clone_dir)],
            check=True,
        )
        # Now ask git to materialise only the docs folder.
        subprocess.run(
            ["git", "-C", str(clone_dir), "sparse-checkout", "set", cfg["docs_path"]],
            check=True,
        )

        docs_root = clone_dir / cfg["docs_path"]
        copied = 0
        for file in sorted(docs_root.rglob("*")):
            if file.suffix not in {".md", ".mdx"} or not file.is_file():
                continue
            relative = file.relative_to(docs_root).as_posix()
            if is_excluded(relative, cfg["exclude"]):
                continue
            destination = target / relative
            destination.parent.mkdir(parents=True, exist_ok=True)
            shutil.copyfile(file, destination)
            copied += 1

    print(f"[{key}] copied {copied} markdown files -> {target.relative_to(ROOT)}")
    return copied


def main() -> None:
    DOCS_DIR.mkdir(parents=True, exist_ok=True)
    total = sum(download_source(key, cfg) for key, cfg in SOURCES.items())
    print(f"Done. {total} markdown files across {len(SOURCES)} sources.")


if __name__ == "__main__":
    main()

6. Step 2: clean and chunk (pipeline/build_corpus.py)

Cleaning

Hugging Face docs start with a licence comment and contain doc-builder tags like <Tip> and [[autodoc]] peft.LoraConfig. The OpenAI docs use mkdocs directives like ::: agents.Agent. None of these help a learner, and they waste tokens. clean_markdown() removes HTML comments and any line that is only such a tag. For each page it also extracts:

  • the title: the first # heading
  • the public URL: page_url() knows that Hugging Face URLs drop the extension, and that the mkdocs site uses folder-style URLs ending in /

Heading-aware chunking

Fixed-size chunking (say, every 500 tokens) cuts a code example in half and mixes the end of one topic with the start of the next. We chunk the way a human would split the page:

  1. split_into_sections() cuts the page at markdown headings and tracks the heading path (LoRA > Initialization). It flips an in_code flag at every ``` fence, so a # comment inside Python code is never mistaken for a heading.
  2. chunk_page() packs small neighbouring sections together until a chunk reaches ~600 tokens.
  3. A section that is too big on its own is split at blank lines (paragraphs). A single paragraph that is still too big, like a long table, is split line by line.
  4. Chunks under 15 tokens (a lone heading) are dropped.

Token counts are estimated as len(text) // 4, since English averages about 4 characters per token. That's accurate enough for sizing chunks and needs no tokenizer download.

The contextual header

A chunk that says "Set r=16 for most tasks" means nothing on its own. Before indexing we prepend where it came from, so both the embedding and BM25 see the context:

Full source: pipeline/build_corpus.py
"""
Step 2 of the data pipeline: clean the markdown and cut it into chunks.

Author: Shivank Agrawal
Project: AI Tutor (Agentic RAG) - Future with Shivank

Input : data/docs/<source>/**/*.md   (from step 1)
Output: data/documents.jsonl  - one cleaned page per line (used by step 3, the KB)
        data/chunks.jsonl     - search-sized pieces of each page (used by step 4
                                and by the keyword search at runtime)

Chunking is "heading-aware": we split a page at its markdown headings first,
never inside a ``` code block, then pack neighbouring sections together until
a chunk reaches ~CHUNK_TOKENS. Every chunk remembers its heading path
(e.g. "LoRA > Initialization"), which we prepend before embedding so a small
chunk still carries the context of where it came from.

Run from the project root:
    python -m pipeline.build_corpus
"""

import json
import re
from pathlib import Path

from app.config import CHUNK_TOKENS, CHUNKS_FILE, DOCS_DIR, DOCUMENTS_FILE, SOURCES

HEADING_RE = re.compile(r"^(#{1,6})\s+(.+?)\s*#*\s*$")
HTML_COMMENT_RE = re.compile(r"<!--.*?-->", re.DOTALL)
# Lines that are only a JSX/HTML tag (<Tip>, </hfoption>, ...), a HF doc-builder
# directive ([[autodoc]] ...), or an mkdocs API directive (::: agents.Agent).
NOISE_LINE_RE = re.compile(r"^\s*(</?[A-Za-z][^>]*>|\[\[.*\]\]|:::\s.*)\s*$")


def count_tokens(text: str) -> int:
    """Rough token count: ~4 characters per token for English text and code."""
    return len(text) // 4 + 1


# ---------------------------------------------------------------------------
# Cleaning and metadata
# ---------------------------------------------------------------------------
def clean_markdown(text: str) -> str:
    """Remove licence headers, doc-builder tags and extra blank lines."""
    text = HTML_COMMENT_RE.sub("", text)
    lines = [line for line in text.splitlines() if not NOISE_LINE_RE.match(line)]
    text = "\n".join(lines)
    return re.sub(r"\n{3,}", "\n\n", text).strip()


def page_title(text: str, path: Path) -> str:
    """First '# Heading' of the page, otherwise a title made from the file name."""
    for line in text.splitlines():
        match = HEADING_RE.match(line)
        if match and len(match.group(1)) == 1:
            return match.group(2).strip()
    return path.stem.replace("_", " ").replace("-", " ").title()


def page_url(key: str, relative: str) -> str:
    """Public URL of the page, so the tutor can cite the real documentation."""
    base = SOURCES[key]["url_base"]
    slug = re.sub(r"\.mdx?$", "", relative)
    if key == "openai_agents":  # mkdocs site: folder-style URLs ending in '/'
        slug = re.sub(r"(^|/)index$", "", slug)
        return base + (slug + "/" if slug else "")
    if slug == "index":  # Hugging Face doc-builder site
        return base
    return base + slug


# ---------------------------------------------------------------------------
# Heading-aware chunking
# ---------------------------------------------------------------------------
def split_into_sections(text: str) -> list[tuple[str, str]]:
    """Cut a page at its headings -> [(heading_path, section_text), ...].

    Lines inside ``` code fences are never treated as headings, because a
    '# comment' in Python code is not a markdown heading.
    """
    sections: list[tuple[str, str]] = []
    path: list[str] = []
    buffer: list[str] = []
    in_code = False

    def flush() -> None:
        body = "\n".join(buffer).strip()
        if body:
            sections.append((" > ".join(path), body))

    for line in text.splitlines():
        if line.lstrip().startswith("```"):
            in_code = not in_code
        match = None if in_code else HEADING_RE.match(line)
        if match:
            flush()
            buffer = []
            level = len(match.group(1))
            path = path[: level - 1] + [match.group(2).strip()]
        buffer.append(line)
    flush()
    return sections


def pack(parts: list[str], separator: str, max_tokens: int) -> list[str]:
    """Greedily join parts with `separator` while the result stays under max_tokens."""
    pieces, current = [], ""
    for part in parts:
        candidate = f"{current}{separator}{part}" if current else part
        if current and count_tokens(candidate) > max_tokens:
            pieces.append(current)
            current = part
        else:
            current = candidate
    if current:
        pieces.append(current)
    return pieces


def split_large_section(text: str, max_tokens: int) -> list[str]:
    """A section bigger than one chunk is split on blank lines (paragraphs).
    A single paragraph that is still too big (a long table or code block)
    is split line by line."""
    paragraphs = []
    for paragraph in text.split("\n\n"):
        if count_tokens(paragraph) > max_tokens:
            paragraphs.extend(pack(paragraph.splitlines(), "\n", max_tokens))
        else:
            paragraphs.append(paragraph)
    return pack(paragraphs, "\n\n", max_tokens)


def chunk_page(text: str) -> list[tuple[str, str]]:
    """Pack small neighbouring sections together; split sections that are too big."""
    chunks: list[tuple[str, str]] = []
    current_heading, current_text = "", ""

    for heading, body in split_into_sections(text):
        if count_tokens(body) > CHUNK_TOKENS:
            if current_text:
                chunks.append((current_heading, current_text))
                current_heading, current_text = "", ""
            chunks.extend((heading, piece) for piece in split_large_section(body, CHUNK_TOKENS))
            continue
        candidate = f"{current_text}\n\n{body}" if current_text else body
        if current_text and count_tokens(candidate) > CHUNK_TOKENS:
            chunks.append((current_heading, current_text))
            current_heading, current_text = heading, body
        else:
            current_heading = current_heading or heading
            current_text = candidate
    if current_text:
        chunks.append((current_heading, current_text))
    return chunks


# ---------------------------------------------------------------------------
# Main
# ---------------------------------------------------------------------------
def main() -> None:
    documents, chunks = [], []

    for key, cfg in SOURCES.items():
        source_dir = DOCS_DIR / key
        files = sorted(p for p in source_dir.rglob("*") if p.suffix in {".md", ".mdx"})
        for path in files:
            relative = path.relative_to(source_dir).as_posix()
            text = clean_markdown(path.read_text(encoding="utf-8", errors="ignore"))
            if count_tokens(text) < 30:  # skip near-empty stub pages
                continue
            doc_id = f"{key}/{re.sub(r'\.mdx?$', '', relative)}"
            doc = {
                "doc_id": doc_id,
                "source": key,
                "title": page_title(text, path),
                "url": page_url(key, relative),
                "relative_path": relative,
                "text": text,
            }
            documents.append(doc)

            page_chunks = [(h, b) for h, b in chunk_page(text) if count_tokens(b) >= 15]
            for i, (heading, body) in enumerate(page_chunks):
                # Contextual header: source + page title + heading path
                # (the heading path usually starts with the page title; drop the repeat).
                section = heading
                if section.startswith(doc["title"]):
                    section = section[len(doc["title"]):].lstrip(" >")
                header = f"{cfg['label']} > {doc['title']}" + (f" > {section}" if section else "")
                chunks.append({
                    "chunk_id": f"{doc_id}#{i}",
                    "doc_id": doc_id,
                    "source": key,
                    "title": doc["title"],
                    "url": doc["url"],
                    "heading": heading,
                    "text": body,
                    # What we embed and keyword-index: header + body.
                    "search_text": f"{header}\n\n{body}",
                    "tokens": count_tokens(body),
                })
        print(f"[{key}] {sum(d['source'] == key for d in documents)} pages, "
              f"{sum(c['source'] == key for c in chunks)} chunks")

    with DOCUMENTS_FILE.open("w", encoding="utf-8") as f:
        for doc in documents:
            f.write(json.dumps(doc, ensure_ascii=False) + "\n")
    with CHUNKS_FILE.open("w", encoding="utf-8") as f:
        for chunk in chunks:
            f.write(json.dumps(chunk, ensure_ascii=False) + "\n")

    avg = sum(c["tokens"] for c in chunks) / max(len(chunks), 1)
    print(f"Done. {len(documents)} pages -> {len(chunks)} chunks "
          f"(avg {avg:.0f} tokens) written to {CHUNKS_FILE.name}")


if __name__ == "__main__":
    main()

7. Step 3: the knowledge base (pipeline/build_kb.py)

Vector search answers "which passages look similar to this question?". Sometimes the agent needs something else: read the whole page, find every file that mentions merge_and_unload, or see what topics exist. For that we lay the docs out as files the agent can browse with read-only commands. There are three layers:

LayerWhat's insideUsed for
raw/docs/<source>/…mdOne file per page, with title / url / source / doc_id frontmatterGround truth. The agent cites the URL from the frontmatter.
generated/corpus_manifest.jsonl (every page), headings.jsonl (every heading + line number), symbols.tsv (code names → files)Exact lookups: "where is SFTConfig documented?"

"""
Step 3 of the data pipeline: build the browsable knowledge base (KB).

Author: Shivank Agrawal
Project: AI Tutor (Agentic RAG) - Future with Shivank

Vector search gives the agent "top-k similar passages". The KB gives it a
second way to find things: browse the docs like files on disk with read-only
commands (cat, rg, grep, find ...). The KB has three layers:

    data/kb/raw/        one markdown file per doc page, with a small header
                        (title, url, source). This is the ground truth.
    data/kb/generated/  machine indexes: a manifest of every page, every
                        heading with its line number, and code symbols
                        (LoraConfig, SFTTrainer, function_tool ...).
    data/kb/wiki/       navigation pages: a start page, one page per source
                        (overview written by the LLM) and one page per topic.

The wiki idea follows Andrej Karpathy's "LLM wiki": keep a small, readable map
over the immutable sources, so the agent orients itself in one `cat` instead
of re-discovering the corpus on every question.

Run from the project root (needs OPENAI_API_KEY for the source overviews):
    python -m pipeline.build_kb
"""

import json
import re
from collections import defaultdict

from openai import OpenAI

from app.config import CHAT_MODEL, DOCUMENTS_FILE, KB_DIR, SOURCES

RAW_DIR, WIKI_DIR, GEN_DIR = KB_DIR / "raw", KB_DIR / "wiki", KB_DIR / "generated"
HEADING_RE = re.compile(r"^(#{1,6})\s+(.+?)\s*#*\s*$")
CODE_RE = re.compile(r"```.*?```|`[^`\n]+`", re.DOTALL)
CLASS_RE = re.compile(r"\b[A-Z][A-Za-z0-9]*[a-z][A-Za-z0-9]*\b")
FUNC_RE = re.compile(r"\b([a-z_][a-z0-9_]{2,})\(")
NOT_SYMBOLS = {"True", "False", "None", "Python", "Example", "Note", "Optional", "List", "Dict"}

# Topic pages: a page joins a topic when the keyword is in its title or shows
# up often in its text.
TOPICS = {
    "lora-and-adapters": ("lora", "qlora", "adapter", "loraconfig"),
    "quantization": ("quantization", "quantized", "bitsandbytes", "4-bit", "8-bit"),
    "supervised-fine-tuning": ("sft", "sfttrainer", "supervised fine-tuning", "fine-tune"),
    "preference-and-rl-training": ("dpo", "grpo", "ppo", "reward model", "preference"),
    "agents-and-tools": ("agent", "function_tool", "tool call", "tools"),
    "multi-agent-and-handoffs": ("handoff", "agents as tools", "orchestrat", "multi-agent"),
    "guardrails": ("guardrail",),
    "sessions-and-memory": ("session", "memory", "conversation history"),
    "tracing-and-debugging": ("tracing", "trace", "debug"),
    "merging-and-inference": ("merge_and_unload", "merging", "inference", "vllm"),
}


def raw_path(doc: dict) -> str:
    """Path of a page inside the KB, e.g. raw/docs/peft/developer_guides/lora.md"""
    return f"raw/docs/{doc['doc_id']}.md"


def write(relative: str, content: str) -> None:
    path = KB_DIR / relative
    path.parent.mkdir(parents=True, exist_ok=True)
    path.write_text(content, encoding="utf-8")


# ---------------------------------------------------------------------------
# Layer 1: raw/
# ---------------------------------------------------------------------------
def build_raw(documents: list[dict]) -> None:
    for doc in documents:
        header = (
            "---\n"
            f"title: {json.dumps(doc['title'])}\n"
            f"url: {doc['url']}\n"
            f"source: {doc['source']}\n"
            f"doc_id: {doc['doc_id']}\n"
            "---\n\n"
        )
        write(raw_path(doc), header + doc["text"] + "\n")
    print(f"raw/        {len(documents)} pages")


# ---------------------------------------------------------------------------
# Layer 2: generated/ (machine indexes)
# ---------------------------------------------------------------------------
def build_generated(documents: list[dict]) -> None:
    manifest, headings, symbols = [], [], set()
    for doc in documents:
        path = raw_path(doc)
        manifest.append({"doc_id": doc["doc_id"], "source": doc["source"],
                         "title": doc["title"], "url": doc["url"], "path": path})

        text = (KB_DIR / path).read_text(encoding="utf-8")
        in_code = False
        for number, line in enumerate(text.splitlines(), start=1):
            if line.lstrip().startswith("```"):
                in_code = not in_code
            match = None if in_code else HEADING_RE.match(line)
            if match:
                headings.append({"path": path, "line": number,
                                 "level": len(match.group(1)), "heading": match.group(2)})

        for code in CODE_RE.findall(doc["text"]):
            for name in CLASS_RE.findall(code) + FUNC_RE.findall(code):
                if name not in NOT_SYMBOLS:
                    symbols.add((name, path))

    write("generated/corpus_manifest.jsonl", "".join(json.dumps(r) + "\n" for r in manifest))
    write("generated/headings.jsonl", "".join(json.dumps(h) + "\n" for h in headings))
    write("generated/symbols.tsv", "symbol\tpath\n" + "".join(f"{s}\t{p}\n" for s, p in sorted(symbols)))
    print(f"generated/  {len(manifest)} manifest rows, {len(headings)} headings, {len(symbols)} symbols")

# Layer 3: wiki/ (navigation)
# ---------------------------------------------------------------------------
def write_source_overview(client: OpenAI, key: str, docs: list[dict]) -> str:
    """Ask the LLM to write a short map of one documentation source."""
    listing = "\n".join(
        f"- {raw_path(d)} | {d['title']} | {d['text'][:180].replace(chr(10), ' ')}"
        for d in docs
    )
    prompt = f"""You are writing a navigation page that an AI tutor agent reads
before answering student questions about {SOURCES[key]['label']}.

Here is every page in this documentation (path | title | first words):
{listing}

Write markdown with exactly these parts:
1. A 3-4 sentence paragraph: what this documentation covers and who it is for.
2. "## Start here": the 5 most useful pages for a beginner, as bullets
   "- `<path>`: <why read it>".
3. "## Which page answers which question": 8 bullets mapping a typical
   student question to the best page, as "- <question> -> `<path>`".
Use only paths from the list above. No title line, no extra sections."""
    response = client.responses.create(model=CHAT_MODEL, input=prompt)
    return response.output_text.strip()


def build_wiki(documents: list[dict]) -> None:
    client = OpenAI()
    by_source = defaultdict(list)
    for doc in documents:
        by_source[doc["source"]].append(doc)

    # One page per source: LLM overview + the full list of pages.
    for key, docs in by_source.items():
        print(f"wiki/       writing overview for {key} with {CHAT_MODEL} ...")
        overview = write_source_overview(client, key, docs)
        pages = "\n".join(f"- `{raw_path(d)}`: {d['title']}" for d in docs)
        write(f"wiki/frameworks/{key}.md",
              f"# {SOURCES[key]['label']}\n\n"
              f"<!-- Overview written by {CHAT_MODEL}; page list generated. -->\n\n"
              f"{overview}\n\n## All {len(docs)} pages\n\n{pages}\n")

    # One page per topic: pages that match the topic keywords, across sources.
    topic_counts = {}
    for topic, keywords in TOPICS.items():
        scored = []
        for doc in documents:
            title, text = doc["title"].lower(), doc["text"].lower()
            mentions = sum(text.count(k) for k in keywords)
            in_title = any(k in title for k in keywords)
            if in_title or mentions >= 4:
                scored.append((10 * in_title + min(mentions, 30), doc))
        scored.sort(key=lambda item: -item[0])
        top = [doc for _, doc in scored[:25]]
        topic_counts[topic] = len(top)
        lines = "\n".join(f"- `{raw_path(d)}` ({d['source']}): {d['title']}" for d in top)
        write(f"wiki/topics/{topic}.md",
              f"# Topic: {topic.replace('-', ' ')}\n\n"
              f"Pages that discuss this topic, most relevant first:\n\n{lines}\n")

    # The start page the agent reads first.
    source_lines = "\n".join(
        f"- **{SOURCES[k]['label']}** (`{k}`): {len(by_source[k])} pages -> `wiki/frameworks/{k}.md`"
        for k in by_source
    )
    topic_lines = "\n".join(
        f"- {t.replace('-', ' ')} -> `wiki/topics/{t}.md` ({n} pages)" for t, n in topic_counts.items()
    )
    write("wiki/index.md", f"""# AI Tutor knowledge base: start here

This KB mirrors the documentation the tutor teaches from.

- `raw/docs/<source>/...md`: the real pages (ground truth, cite these).
- `wiki/`: navigation pages like this one (never cite these).
- `generated/`: machine indexes for exact lookups.

## Sources

{source_lines}

## Topics

{topic_lines}

## Exact lookups

- Class or function name: `rg -n -m 20 "LoraConfig" generated/symbols.tsv`
- Section headings: `rg -n -m 20 "rank" generated/headings.jsonl`
- Page titles and URLs: `rg -n -m 20 "quickstart" generated/corpus_manifest.jsonl`
""")
    print(f"wiki/       index + {len(by_source)} source pages + {len(TOPICS)} topic pages")


def main() -> None:
    documents = [json.loads(line) for line in DOCUMENTS_FILE.open(encoding="utf-8")]
    build_raw(documents)
    build_generated(documents)
    build_wiki(documents)
    print("Done. Knowledge base ready in data/kb/")

Each chunk's search_text (header + body) is sent to text-embedding-3-small in batches of 100. The script then stores in a local Chroma collection, on disk at data/chroma/:

"""
Step 4 of the data pipeline: embed every chunk and store it in ChromaDB.

Author: Shivank Agrawal
Project: AI Tutor (Agentic RAG) - Future with Shivank

Each chunk's `search_text` (contextual header + body) is turned into a vector
with OpenAI's embedding model and saved, with its metadata, in a local Chroma
database at data/chroma/. We use `upsert`, so re-running the script after
adding a source only adds/updates chunks; nothing has to be deleted.

Run from the project root (needs OPENAI_API_KEY):
    python -m pipeline.build_vector_store
"""

import json

import chromadb
from openai import OpenAI

from app.config import CHROMA_COLLECTION, CHROMA_DIR, CHUNKS_FILE, EMBED_MODEL

BATCH_SIZE = 100  # chunks per embeddings API call


def main() -> None:
    chunks = [json.loads(line) for line in CHUNKS_FILE.open(encoding="utf-8")]
    client = OpenAI()

    db = chromadb.PersistentClient(path=str(CHROMA_DIR))
    # Cosine distance is the usual choice for OpenAI embeddings.
    collection = db.get_or_create_collection(
        name=CHROMA_COLLECTION, metadata={"hnsw:space": "cosine"}
    )

    for start in range(0, len(chunks), BATCH_SIZE):
        batch = chunks[start:start + BATCH_SIZE]
        response = client.embeddings.create(
            model=EMBED_MODEL, input=[c["search_text"] for c in batch]
        )
        collection.upsert(
            ids=[c["chunk_id"] for c in batch],
            embeddings=[item.embedding for item in response.data],
            documents=[c["text"] for c in batch],
            metadatas=[
                {"source": c["source"], "doc_id": c["doc_id"], "title": c["title"],
                 "url": c["url"], "heading": c["heading"]}
                for c in batch
            ],
        )
        print(f"embedded {min(start + BATCH_SIZE, len(chunks))}/{len(chunks)} chunks")

    print(f"Done. Collection '{CHROMA_COLLECTION}' has {collection.count()} vectors "
          f"({EMBED_MODEL}) in data/chroma/")


if __name__ == "__main__":
    main()

9. retrieval.py: hybrid search

HybridRetriever.search(query, sources) runs four stages:

StageHowWhy
1. Dense searchEmbed the question → Chroma query, top 15, filtered by sourceFinds meaning: "make fine-tuning cheaper" ↔ LoRA pages
2. Keyword searchBM25 (rank_bm25) over all chunks in memory, top 15 in the selected sourcesFinds exact strings: lora_alpha, SFTConfig, error messages
3. FusionReciprocal Rank Fusion: score = Σ 1 / (60 + rank)Merges two lists whose raw scores aren't comparable
4. BudgetTake the best fused chunks until 6 passages or 4,000 tokensBounds what each tool call adds to the context

Why RRF and not "add the scores"?

Cosine similarity lives in about 0.2–0.7, while BM25 scores can be 5 or 40. Adding them lets BM25 dominate. RRF ignores raw scores and uses only ranks:

  • A chunk ranked 1st by vector search and 3rd by BM25 scores 1/61 + 1/63 = 0.0323.
  • A chunk ranked 1st by only one list scores 1/61 = 0.0164.

So agreement between the two methods wins. The constant 60 (from the original RRF paper) keeps the top rank from dominating.

"""
retrieval.py - hybrid search over the chunked documentation.

Author: Shivank Agrawal
Project: AI Tutor (Agentic RAG) - Future with Shivank

One question goes through four stages:

    1. Dense search  : embed the question with OpenAI, ask Chroma for the
                       nearest chunks (good at meaning: "make training cheaper").
    2. Keyword search: BM25 over the same chunks (good at exact words:
                       "LoraConfig", "lora_alpha", error strings).
    3. Fusion        : Reciprocal Rank Fusion merges both ranked lists.
    4. Budget        : keep the best chunks until the token budget is full.

Both searches are filtered to the sources the student selected in the UI.
"""

import json
import re
from functools import lru_cache

import chromadb
from openai import OpenAI
from rank_bm25 import BM25Okapi

from app.config import (
    BM25_TOP_K, CHROMA_COLLECTION, CHROMA_DIR, CHUNKS_FILE, CONTEXT_TOKEN_BUDGET,
    DENSE_TOP_K, EMBED_MODEL, FINAL_TOP_K, RRF_K,
)


def tokenize(text: str) -> list[str]:
    """Lower-case word tokens for BM25 (keeps snake_case names like lora_alpha)."""
    return re.findall(r"[a-z0-9_]+", text.lower())


class HybridRetriever:
    def __init__(self) -> None:
        # All chunks in memory: needed for BM25 and to look chunks up by id.
        self.chunks = [json.loads(line) for line in CHUNKS_FILE.open(encoding="utf-8")]
        self.by_id = {c["chunk_id"]: c for c in self.chunks}
        self.bm25 = BM25Okapi([tokenize(c["search_text"]) for c in self.chunks])

        self.openai = OpenAI()
        db = chromadb.PersistentClient(path=str(CHROMA_DIR))
        self.collection = db.get_collection(CHROMA_COLLECTION)

    # -- stage 1 -----------------------------------------------------------
    def dense_search(self, query: str, sources: list[str]) -> list[str]:
        """Chunk ids ranked by embedding similarity to the question."""
        embedding = self.openai.embeddings.create(model=EMBED_MODEL, input=[query]).data[0].embedding
        result = self.collection.query(
            query_embeddings=[embedding],
            n_results=DENSE_TOP_K,
            where={"source": {"$in": sources}},  # source filter happens inside Chroma
        )
        return result["ids"][0]

    # -- stage 2 -----------------------------------------------------------
    def keyword_search(self, query: str, sources: list[str]) -> list[str]:
        """Chunk ids ranked by BM25 keyword score."""
        scores = self.bm25.get_scores(tokenize(query))
        ranked = sorted(range(len(self.chunks)), key=lambda i: scores[i], reverse=True)
        ids = []
        for i in ranked:
            if scores[i] <= 0:
                break
            if self.chunks[i]["source"] in sources:
                ids.append(self.chunks[i]["chunk_id"])
            if len(ids) == BM25_TOP_K:
                break
        return ids

    # -- stages 3 + 4 --------------------------------------------------------
    def search(self, query: str, sources: list[str]) -> list[dict]:
        """Full hybrid pipeline. Returns the passages the agent will read."""
        dense_ids = self.dense_search(query, sources)
        keyword_ids = self.keyword_search(query, sources)

        # Reciprocal Rank Fusion: score = sum over lists of 1 / (k + rank).
        # A chunk ranked high in BOTH lists beats one that is first in only one.
        fused: dict[str, float] = {}
        for ranked_ids in (dense_ids, keyword_ids):
            for rank, chunk_id in enumerate(ranked_ids, start=1):
                fused[chunk_id] = fused.get(chunk_id, 0.0) + 1.0 / (RRF_K + rank)

        results, used_tokens = [], 0
        for chunk_id, score in sorted(fused.items(), key=lambda kv: kv[1], reverse=True):
            chunk = self.by_id[chunk_id]
            if used_tokens + chunk["tokens"] > CONTEXT_TOKEN_BUDGET:
                continue  # too big for what is left of the budget; try the next one
            used_tokens += chunk["tokens"]
            results.append({
                "rank": len(results) + 1,
                "score": round(score, 4),
                "found_by": [name for name, ids in (("vector", dense_ids), ("keyword", keyword_ids))
                             if chunk_id in ids],
                "source": chunk["source"],
                "title": chunk["title"],
                "heading": chunk["heading"],
                "url": chunk["url"],
                "text": chunk["text"],
            })
            if len(results) == FINAL_TOP_K:
                break
        return results


@lru_cache(maxsize=1)
def get_retriever() -> HybridRetriever:
    """Build the retriever once (loading BM25 + Chroma takes a moment) and reuse it."""
    return HybridRetriever()

10. kb_shell.py: a safe shell for an LLM

Giving a model a shell is powerful and dangerous. The model's command is untrusted input: it could be confused, or steered by a prompt injection hidden in a document it just read. So nothing reaches the operating system without passing five guards:

  1. No shell at all. The command is split with shlex.split and run as an argv list with subprocess.run(..., shell=False). Characters like | ; & > < ` $ are rejected up front, so pipes, redirects, chaining and $(...) can't happen.
  2. Program allow-list. Only rg grep find ls sed head cat wc, all read-only.
  3. Option allow-list per program. sed is only allowed as sed -n A,Bp FILE, so sed -i (edit in place) is impossible. find accepts only -maxdepth/-mindepth/-type/-name/-iname, so -exec and -delete are impossible. rg --pre, which runs a program, is rejected.
  4. Path jail. (KB_DIR / path).resolve() must be inside KB_DIR. resolve() collapses ../, and is_relative_to then checks containment. Absolute paths are refused.
  5. Limits. An 8-second timeout, a 12,000-character output cap, mandatory -m N for searches over a raw/ folder, and at most 8 commands per question (enforced in agent.py).

Every error message names the allowed form. The model reads the error as a tool result and fixes its own command on the next try.

    "grep": {"-m"},

FIND_OPTIONS = {"-maxdepth", "-mindepth", "-type", "-name", "-iname"}

USAGE = (

class KbCommandError(ValueError):
    """Raised when a command breaks one of the safety rules."""


@dataclass
class KbResult:
    command: str
    output: str
    exit_code: int
    read_paths: list[str] = field(default_factory=list)  # raw/ files that were read


# ---------------------------------------------------------------------------
# Guards
# ---------------------------------------------------------------------------
def jail_path(path: str) -> str:
    """Accept a path only if it stays inside the KB folder."""
    if path.startswith(("/", "~")):
        raise KbCommandError(f"absolute paths are not allowed: {path} (use paths like raw/docs/...)")
    resolved = (KB_DIR / path).resolve()
    if not resolved.is_relative_to(KB_DIR.resolve()):
        raise KbCommandError(f"path escapes the knowledge base: {path}")
    return path


def split_options(program: str, args: list[str]) -> tuple[list[str], list[str]]:
    """Separate allowed options from positional arguments; reject anything else."""
    options, positional, i = [], [], 0
    while i < len(args):
        arg = args[i]
        if arg == "--":  # everything after -- is positional
            positional.extend(args[i + 1:])
            break
        if arg.startswith("-") and not positional:
            if arg in FLAGS.get(program, set()):
                options.append(arg)
            elif arg in VALUE_OPTIONS.get(program, set()) and i + 1 < len(args):
                options.extend([arg, args[i + 1]])
                i += 1
            else:
                raise KbCommandError(f"option {arg} is not allowed for {program}. {USAGE}")
        else:
            positional.append(arg)
        i += 1
    return options, positional


def build_argv(command: str) -> tuple[list[str], list[str]]:
    """Validate a command and return (argv to execute, raw/ files it reads)."""
    if not command.strip():
        raise KbCommandError("empty command")
    if any(ch in FORBIDDEN_CHARS for ch in command):
        raise KbCommandError("pipes, redirects, chaining and $ are not allowed. One command per call.")
    tokens = shlex.split(command)
    program, args = tokens[0], tokens[1:]

    if program in ("rg", "grep"):
        options, positional = split_options(program, args)
        if not positional:
            raise KbCommandError(f"{program} needs a PATTERN. {USAGE}")
        pattern, paths = positional[0], [jail_path(p) for p in positional[1:]]
        # "Broad" = no path, or a folder under raw/ (thousands of possible hits).
        broad = not paths or any(p.startswith("raw") and (KB_DIR / p).is_dir() for p in paths)
        if broad and "-m" not in options:
            raise KbCommandError(f"broad {program} searches must limit matches with -m N (e.g. -m 20)")
        if program == "grep" and paths and any((KB_DIR / p).is_dir() for p in paths) and "-r" not in options:
            options.append("-r")  # grep needs -r to search inside a folder
        return [program, *options, "--", pattern, *paths], []

    if program == "find":
        argv, i = ["find"], 0
        if args and not args[0].startswith("-"):
            argv.append(jail_path(args[0]))
            i = 1
        else:
            argv.append(".")
        while i < len(args):
            option = args[i]
            if option not in FIND_OPTIONS or i + 1 >= len(args):
                raise KbCommandError(f"find only accepts -maxdepth/-mindepth/-type/-name/-iname. {USAGE}")
            value = args[i + 1]
            if option == "-type" and value not in ("f", "d"):
                raise KbCommandError("find -type must be f or d")
            if option in ("-maxdepth", "-mindepth") and not value.isdigit():
                raise KbCommandError(f"find {option} needs a number")
            argv.extend([option, value])
            i += 2
        return argv, []

    if program == "ls":
        options, positional = split_options(program, args)
        return ["ls", *options, *[jail_path(p) for p in positional]], []

    if program == "sed":
        if len(args) != 3 or args[0] != "-n" or not re.fullmatch(r"\d+,\d+p", args[1]):
            raise KbCommandError("sed is only allowed as: sed -n START,ENDp FILE")
        path = jail_path(args[2])
        return ["sed", "-n", args[1], path], [path]

    if program == "head":
        lines, files = "40", list(args)
        if files and files[0] == "-n" and len(files) > 1:
            lines, files = files[1], files[2:]
        elif files and re.fullmatch(r"-\d+", files[0]):
            lines, files = files[0][1:], files[1:]
        if not lines.isdigit() or not files:
            raise KbCommandError("head is only allowed as: head -n N FILE")
        paths = [jail_path(p) for p in files]
        return ["head", "-n", lines, *paths], paths

    if program == "cat":
        if not 1 <= len(args) <= 3 or any(a.startswith("-") for a in args):
            raise KbCommandError("cat takes 1 to 3 files and no options")
        paths = [jail_path(p) for p in args]
        return ["cat", *paths], paths

    if program == "wc":
        options, positional = split_options(program, args)
        return ["wc", *options, *[jail_path(p) for p in positional]], []

    raise KbCommandError(f"'{program}' is not allowed. {USAGE}")


# ---------------------------------------------------------------------------
# Execution
# ---------------------------------------------------------------------------
def execute_kb_command(command: str) -> KbResult:
    """Validate, run and return the (size-capped) output of one KB command."""
    try:
        argv, read_paths = build_argv(command)
    except (KbCommandError, ValueError) as error:  # ValueError: bad quoting in shlex
        return KbResult(command, f"$ {command}\nerror: {error}", exit_code=2)

    try:
        completed = subprocess.run(
            argv, cwd=KB_DIR, capture_output=True, text=True,
            timeout=KB_COMMAND_TIMEOUT, shell=False,  # shell=False: no shell features at all
        )
    except FileNotFoundError:
        return KbResult(command, f"$ {command}\nerror: {argv[0]} is not installed here. "
                                 "Use grep -rn -m 20 PATTERN PATH instead.", exit_code=127)
    except subprocess.TimeoutExpired:
        return KbResult(command, f"$ {command}\nerror: timed out after {KB_COMMAND_TIMEOUT}s; "
                                 "narrow the path or add -m.", exit_code=124)

    output = completed.stdout + completed.stderr
    if completed.returncode == 1 and not output.strip():
        output = "(no matches)"
    if len(output) > KB_MAX_OUTPUT_CHARS:
        output = output[:KB_MAX_OUTPUT_CHARS] + "\n[output truncated: use sed -n or head to read a smaller part]"
    raw_reads = [p for p in read_paths if p.startswith("raw/")]
    return KbResult(command, f"$ {command}\n{output}", completed.returncode, raw_reads)


@lru_cache(maxsize=1)
def manifest_by_path() -> dict[str, dict]:
    """raw/ path -> {title, url, source}, used to turn files read into citations."""
    rows = (json.loads(line) for line in (KB_DIR / "generated/corpus_manifest.jsonl").open(encoding="utf-8"))
    return {row["path"]: row for row in rows}

@dataclass(frozen=True)

# ---------------------------------------------------------------------------
# Tools. The docstring is the description the model sees.
# response_format="content_and_artifact": the tool returns (text for the

# ---------------------------------------------------------------------------
@tool(response_format="content_and_artifact")
def retrieve_tutor_context(query: str, runtime: ToolRuntime[TutorContext]) -> tuple[str, list[dict]]:
    """Search the course documentation with hybrid vector + keyword search.
    Returns the most relevant passages with their title and URL.
    Pass exactly ONE focused query string per call."""
    passages = get_retriever().search(query, list(runtime.context.sources))
    if not passages:
        return "No passages found in the selected sources. Try other keywords or run_kb_command.", []

    citations = [{"title": p["title"], "url": p["url"], "source": p["source"]} for p in passages]
    return content, citations


@tool(response_format="content_and_artifact")
def run_kb_command(command: str) -> tuple[str, list[dict]]:
    """Run ONE read-only command inside the knowledge base folder:
    rg, grep, find, ls, `sed -n START,ENDp FILE`, head, cat or wc.
    Paths are relative to the KB root: raw/, wiki/, generated/.
    No pipes, redirects or chaining."""

    citations = [
        {"title": manifest[p]["title"], "url": manifest[p]["url"], "source": manifest[p]["source"]}
        for p in result.read_paths if p in manifest
    ]
    return result.output, citations

def get_agent():

        model=ChatOpenAI(model=CHAT_MODEL),
        tools=[retrieve_tutor_context, run_kb_command],
        middleware=[

            # message telling the model to answer with what it has.
            ToolCallLimitMiddleware(tool_name="run_kb_command", run_limit=KB_COMMAND_LIMIT),
        ],
        context_schema=TutorContext,
        checkpointer=InMemorySaver(),  # conversation memory, keyed by thread_id
    )


async def stream_chat(message: str, thread_id: str, sources: list[str]) -> AsyncIterator[dict]:
    """Run one student turn and yield UI events as they happen.

    Event types: tool-call, tool-result, text-delta, sources, finish.
    """
    agent = get_agent()
    citations: dict[str, dict] = {}  # url -> citation, de-duplicated

    # stream_mode="messages" gives answer tokens as they are generated;
    # stream_mode="updates" gives each finished step (tool calls, tool results).
    async for mode, data in agent.astream(
        {"messages": [{"role": "user", "content": message}]},
        config={"configurable": {"thread_id": thread_id}},
        context=TutorContext(sources=tuple(sources)),
        stream_mode=["messages", "updates"],
    ):
        if mode == "messages":
            chunk, _metadata = data
            # AIMessageChunk = a streamed token; a full AIMessage arrives
            # instead if the model call was not streamed.
            if isinstance(chunk, (AIMessageChunk, AIMessage)) and chunk.text:
                yield {"type": "text-delta", "delta": chunk.text}
            continue

        for update in data.values():  # mode == "updates": {node_name: update}
            if not isinstance(update, dict):
                continue
            for msg in update.get("messages", []):
                if isinstance(msg, AIMessage) and msg.tool_calls:
                    for call in msg.tool_calls:
                        yield {"type": "tool-call", "id": call["id"],
                               "name": call["name"], "args": call["args"]}
                elif isinstance(msg, ToolMessage):
                    for citation in msg.artifact or []:
                        citations.setdefault(citation["url"], citation)
                    yield {"type": "tool-result", "id": msg.tool_call_id,
                           "name": msg.name, "preview": str(msg.content)[:300]}

    yield {"type": "sources", "sources": list(citations.values())}
    yield {"type": "finish"}

Author: Shivank Agrawal

Endpoints
    GET  /           -> the chat page (frontend/index.html)

Why streaming? An agent may search 2-4 times before it answers. With SSE the
student sees each step live ("searching LoRA rank...") and the answer appears
word by word, instead of staring at a spinner for 10+ seconds.

Each SSE message is one line:  data: {"type": "...", ...}\n\n

Run from the project root:

import json
import os
import uuid

import uvicorn
from fastapi import FastAPI, HTTPException
from fastapi.responses import FileResponse, StreamingResponse
from pydantic import BaseModel

from app.agent import retrieve_tutor_context, run_kb_command, stream_chat
from app.config import CHAT_MODEL, DOCUMENTS_FILE, ROOT, SOURCES

app = FastAPI(title="AI Tutor (Agentic RAG)")


class ChatRequest(BaseModel):
    message: str  # only the NEW message; history lives on the server
    threadId: str | None = None  # empty/None = start a new conversation
    sources: list[str] | None = None  # None = all sources


def page_counts() -> dict[str, int]:
    """How many pages each source has (shown next to the checkbox)."""
    counts = {key: 0 for key in SOURCES}
    if DOCUMENTS_FILE.exists():
        for line in DOCUMENTS_FILE.open(encoding="utf-8"):
            counts[json.loads(line)["source"]] += 1
    return counts


@app.get("/")
def index() -> FileResponse:
    return FileResponse(ROOT / "frontend" / "index.html")


@app.get("/api/tools")
def tools() -> dict:
    counts = page_counts()
    return {
        "model": CHAT_MODEL,
        "tools": [{"name": t.name, "description": t.description}
                  for t in (retrieve_tutor_context, run_kb_command)],
        "sources": [{"key": key, "label": cfg["label"], "pages": counts[key]}
                    for key, cfg in SOURCES.items()],
    }


@app.post("/api/chat")
async def chat(request: ChatRequest) -> StreamingResponse:
    if not request.message.strip():
        raise HTTPException(status_code=422, detail="message is empty")
    sources = request.sources or list(SOURCES)
    unknown = [s for s in sources if s not in SOURCES]
    if unknown:
        raise HTTPException(status_code=422, detail=f"unknown sources: {unknown}")
    thread_id = request.threadId or str(uuid.uuid4())

    async def event_stream():
        def sse(event: dict) -> str:
            return f"data: {json.dumps(event, ensure_ascii=False)}\n\n"

        # First event tells the client which conversation this is, so it can
        # send the same threadId with the next question (that's the memory).
        yield sse({"type": "thread", "threadId": thread_id})
        try:
            async for event in stream_chat(request.message, thread_id, sources):
                yield sse(event)
        except Exception as error:  # show the problem in the UI instead of a silent hang
            yield sse({"type": "error", "message": f"{type(error).__name__}: {error}"})

    return StreamingResponse(event_stream(), media_type="text/event-stream")

  • tool-call adds a step line, and the matching tool-result (same id) turns it into a ✓.
  • text-delta appends to the answer and re-renders the markdown. It goes through DOMPurify because model output must never be trusted as HTML.
  • thread stores the threadId, which is sent with the next question. "New chat" just clears it.

We use fetch + ReadableStream instead of the browser's EventSource, because EventSource only supports GET and we need to POST a JSON body.

function addMessage(role, html) {
  const div = document.createElement("div");
  div.className = "msg " + role;
  div.innerHTML = `<div class="bubble">${html}</div>`;
  document.getElementById("chat").appendChild(div);
  div.scrollIntoView({ block: "end" });

function escapeHtml(text) {
  return text.replace(/[&<>"]/g, c => ({ "&": "&amp;", "<": "&lt;", ">": "&gt;", '"': "&quot;" }[c]));
}

// 2) Send a question and 3) render the SSE stream as it arrives.
async function send(message) {
  const sources = selectedSources();
  if (!sources.length) { alert("Select at least one source."); return; }
  addMessage("user", escapeHtml(message));
  const bubble = addMessage("tutor", `<div class="steps"></div><div class="answer"></div><div class="sources"></div>`);
  const stepsEl = bubble.querySelector(".steps"), answerEl = bubble.querySelector(".answer");
  let answer = "";

  const response = await fetch("/api/chat", {
    method: "POST",
    headers: { "Content-Type": "application/json" },
    body: JSON.stringify({ message, threadId, sources }),
  });
  const reader = response.body.getReader();
  const decoder = new TextDecoder();
  let buffer = "";

  while (true) {
    const { value, done } = await reader.read();
    if (done) break;
    buffer += decoder.decode(value, { stream: true });
    const events = buffer.split("\n\n");
    buffer = events.pop();  // keep an incomplete event for the next read
    for (const raw of events) {
      if (!raw.startsWith("data: ")) continue;
      const event = JSON.parse(raw.slice(6));

      if (event.type === "thread") threadId = event.threadId;
      if (event.type === "tool-call") {
        const arg = event.args.query || event.args.command || JSON.stringify(event.args);
        stepsEl.insertAdjacentHTML("beforeend",
          `<div class="step running" id="step-${event.id}">${event.name}: ${escapeHtml(arg)}</div>`);
      }
      if (event.type === "tool-result") {
        const step = document.getElementById("step-" + event.id);
        if (step) step.className = "step done";
      }
      if (event.type === "text-delta") {
        answer += event.delta;
        answerEl.innerHTML = DOMPurify.sanitize(marked.parse(answer));
      }
      if (event.type === "sources") {
        bubble.querySelector(".sources").innerHTML = event.sources.map(s =>
          `<a href="${s.url}" target="_blank" rel="noopener">${escapeHtml(s.title)} · ${s.source}</a>`).join("");
      }
      if (event.type === "error") {
        answerEl.innerHTML += `<p class="error">${escapeHtml(event.message)}</p>`;
      }
      bubble.scrollIntoView({ block: "end" });
    }
  }
}

17. What a production version adds

This project keeps the core architecture and leaves out what you'd add before real users arrive. Knowing this list is what separates a demo from an engineer.

  • Reranking after RRF, with a cross-encoder or a rerank API, to reorder the top 30 down to the best 5.
  • Contextual retrieval: an LLM writes one sentence situating each chunk in its page before embedding.
  • Context management for long chats: summarise older turns and clear old tool outputs, so the context doesn't grow without limit.
  • Persistent memory: a Postgres checkpointer, and eviction of idle threads.
  • Reliability:
    • retries
    • a fallback model when the provider is down
    • a soft failure when retrieval errors ("search is unavailable, answering from general knowledge")
  • Abuse controls: per-IP rate limits on /api/chat, and rejecting known prompt-injection scaffolds before they reach the model.
  • Observability:
    • tracing every run (LangSmith or OpenTelemetry)
    • per-turn token, cost and time-to-first-token stats
    • alerts
  • Evals: a fixed question set with expected source pages (retrieval hit@k) and graded answers (faithfulness, citation correctness), run on every change.
  • Citation verification: check that every URL in the answer came from a tool result in this turn.

18. Interview follow-up questions

Q1. Why an agent? Isn't a single RAG call cheaper and faster?
It is cheaper per question, but it fails on comparisons (one search covers one topic), exact identifiers, and partial chunks. The agent spends extra calls only when the question needs them: a greeting costs one call and a comparison costs three to five. Test 2 shows the parallel searches, and test 4 shows the KB lookup a fixed chain can't do.
Q2. How do you stop the agent from looping forever or burning money?
There are three layers:
  • ToolCallLimitMiddleware caps KB commands per question.
  • The prompt limits sequential searches to 2.
  • Each tool caps its output (6 passages / 4,000 tokens, 12,000 characters).
In production you'd also add a model-call limit (ModelCallLimitMiddleware) and a per-request timeout.
Q3. Walk me through RRF. Why k = 60?
Each list contributes 1/(k + rank) per item, and the contributions are summed. It needs only ranks, so it merges scores on different scales. k dampens the gap between rank 1 and rank 2. With k = 60, being in both lists matters more than being first in one. 60 is the value from the original paper and works well without tuning.
Q4. What's the most dangerous part of this system, and how did you secure it?
The shell tool. The command comes from the model, and the model can be steered by injected text in a document it reads. The defences are: no shell (argv + shell=False), a program allow-list, a per-program option allow-list (no sed -i, find -exec, rg --pre), a path jail with resolve() + is_relative_to, and timeouts and output caps. In production you'd also run it in a container with a read-only filesystem.
Q5. How does the source filter work end to end?
The UI sends sources → FastAPI validates them → they become TutorContext.sources → the retrieval tool reads them from runtime.context (not from the model). They become a Chroma where filter and a BM25 post-filter. The prompt middleware also lists them, so KB browsing prefers those folders. The model cannot change the filter, because the filter is not in its tool schema.
Q6. How does conversation memory work, and what breaks at scale?
The checkpointer stores the full message list per thread_id, and the client sends only the new message plus the id. At scale there are three problems:
  • Memory lives in one process: you need Postgres and sticky-free scaling.
  • Threads never expire: you need a TTL.
  • Long threads grow the context: you need summarisation middleware or trimming of old tool outputs.
Q7. How would you evaluate this tutor?
Split it into two parts:
  • Retrieval: 50 questions labelled with the page that answers each, measured as hit@6 and MRR for vector-only vs BM25-only vs hybrid.
  • Generation: faithfulness (is every claim supported by a retrieved passage?), citation precision, and refusal correctness on out-of-scope questions, graded by an LLM judge that's checked against human labels.
Run both on every prompt or chunking change.
Q8. A learner says the tutor cited a page that doesn't say that. How do you debug it?
Replay the turn using the trace or ask.py, and look at the tool results. Was the claim in a passage at all? If not, it's a generation problem: tighten the answer rules or verify citations. If the right page was never retrieved, it's a retrieval problem: check the chunking around that section and try the query against each search method. Then add the case to the eval set.
Q9. Why put a contextual header on each chunk? Why not just store it as metadata?
Metadata isn't embedded and isn't keyword-indexed. A chunk saying "set it to 16" only matches a LoRA-rank question if "LoRA" and "rank" are in the text that gets embedded and indexed. The header puts them there for a few extra tokens per chunk.
Q10. Why does content_and_artifact matter?
It separates what the model needs (passage text) from what the application needs (structured citations). Without it you'd have to parse URLs back out of the model's text, or show the model metadata that only wastes tokens. The artifact rides on the ToolMessage, and the model never sees it.
Q11. The docs get updated weekly. How do you keep the index fresh?
Schedule the pipeline:
  • A sparse clone of the latest commit.
  • Hash each page and re-chunk and re-embed only the pages that changed. upsert makes this natural because chunk ids are stable (doc_id#n).
  • Delete chunks of pages that disappeared, and rebuild the KB.
Record the commit SHA per source so answers can say which version they reflect.
Q12. How would you add a fourth library, say LangGraph?
Add one entry to SOURCES (repo, docs folder, URL base, excludes), then run the four pipeline steps. The UI picker, retrieval filter, wiki and prompt pick it up automatically, because everything reads that one dict. You might also add topic keywords for the wiki.
